# Правила ИИ-агента Lootly

## Обязательные правила

1. Не придумывать внешние API, endpoint-ы, лимиты или возможности площадок.
2. Не считать undocumented behavior стабильным контрактом.
3. Не добавлять обход CAPTCHA, fingerprinting, proxy rotation или иные механизмы обхода защит без явного отдельного юридического и технического решения владельца проекта.
4. Не коммитить токены, cookies, пароли, приватные ключи и .env.
5. Не изменять production schema без миграции.
6. Не выполнять необратимые миграции без явного плана rollback.
7. Не смешивать source adapter и core business logic.
8. Любая новая бизнес-логика должна иметь тесты.
9. Любая интеграция с внешним сервисом должна иметь timeout, retries и обработку ошибок.
10. Все фоновые операции должны быть идемпотентными.
11. Повторная доставка события не должна приводить к повторному уведомлению или порче данных.
12. Все денежные значения хранить без float.
13. Даты хранить в UTC.
14. Для логов использовать structured logging.
15. Пользовательские URL и входные данные валидировать.
16. Исключить SSRF через source URL.
17. Перед добавлением зависимости проверить, действительно ли она нужна.
18. Не усложнять архитектуру раньше времени.
19. Оптимизировать только после измерений.
20. Предпочитать ясность кода clever-решениям.

## Правила работы с требованиями

При конфликте приоритет:
1. безопасность;
2. технические ограничения;
3. бизнес-требования;
4. архитектурные соглашения;
5. локальная реализация.

Если задача расходится с документированными требованиями, агент должен явно зафиксировать расхождение в PR.
