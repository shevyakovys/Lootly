# Правила ИИ-агентов Lootly

1. Не смешивать booking domain с HTTP/transport деталями.
2. Не использовать float для денег.
3. Persistence timestamps хранить timezone-aware UTC.
4. Timezone филиала должна быть IANA timezone string.
5. Не допускать создания двух активных записей одного сотрудника на пересекающееся время.
6. Проверка доступности и создание записи должны учитывать concurrency.
7. Не удалять историю записей физически без отдельного требования; отмена — статус.
8. Изменение production schema только через миграцию.
9. Миграции должны иметь downgrade, если это технически возможно.
10. Секреты, токены и пароли не коммитить.
11. Персональные данные клиентов не писать в логи без необходимости.
12. Внешние уведомления/платежи должны иметь timeout и retries.
13. Повторная доставка команды не должна создавать вторую запись.
14. Любая новая бизнес-логика покрывается тестами.
15. Ошибки domain должны быть отделены от HTTP ошибок.
16. Не усложнять архитектуру до появления требования.
17. Все изменения после реализации проходят независимый QA.
18. Не завершать задачу при падающих обязательных quality gates.
19. Исправимый дефект: диагностика → исправление → повторная проверка.
20. Один блокер: максимум 3 самостоятельные итерации.
21. После третьей неудачи остановиться и сообщить симптом, логи, попытки и нужное решение.
22. При поручении продолжать разработку не запрашивать подтверждение между успешными этапами.
23. Запрашивать пользователя раньше только если нужен продуктовый выбор, credential или внешний доступ.

## Booking invariants

- appointment.end_at > appointment.start_at;
- duration услуги > 0;
- цена услуги >= 0;
- активная запись относится к существующим organization/location/staff/service/customer;
- услуга должна быть назначена выбранному сотруднику;
- запись должна помещаться в рабочее время;
- time off блокирует слот;
- canceled appointment не блокирует слот;
- timezone преобразования должны тестироваться на переходах DST там, где это применимо.
